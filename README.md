> 一套 Python 代码，同时产出 **电脑版（Windows / macOS / Linux）** 和 **手机版（Android / iOS）**。

## 一、Python 还是 C？建议选 Python

先给结论：**这个项目用 Python，别用 C。**

| 对比项 | Python（推荐） | C 语言 |
| --- | --- | --- |
| 写图形界面 | PyQt / Tkinter / Flet，几十行就是一个窗口 | 得直接调 Win32 API 或 GTK，光一个输入框就上百行 |
| 跨平台 | 同一份代码跑 Windows / macOS / Linux | 每个系统都要写一套，代码基本没法复用 |
| 手机版 | Flet / Kivy 一套代码直接打包 APK、IPA | 得分别学 Java/Kotlin（安卓）和 Swift（iOS），等于再做两个 App |
| 中文处理 | 原生 Unicode，`str` 直接处理中文 | 要自己管编码、内存，处理中文极易踩坑 |
| 文本解析（本项目核心） | 正则 + 字典，几十行搞定 | 字符串处理要手写，代码量至少 5 倍 |
| 打包发布 | `flet build apk` / `exe` 一条命令 | 没有统一打包工具，各平台各配一套 |
| 性能 | 够用（解析几 KB 文本，毫秒级） | 更快，但这里完全用不上 |
| 学习/调试成本 | 低，报错看得懂 | 高，段错误能查一整天 |

**什么时候才考虑 C**：写操作系统、驱动、单片机、高频交易、对延迟极其敏感的核心模块。
歌词工具是典型的"轻计算 + 重界面"应用，C 的性能优势用不上，开发成本却高一个数量级。

> 小提示：真遇到性能瓶颈时，正确做法也是 **Python 写主体 + C 写热点模块**，而不是全用 C 重写。

## 二、功能清单

| 功能 | 说明 |
| --- | --- |
| **三行模板** | 第 1 行作词、第 2 行作曲、第 3 行编曲，第 4 行起是歌词正文 |
| **信息区自动展开** | 导入后「歌曲信息」自动展开，作词/作曲/编曲一眼可见，不用再点开 |
| **改名自动同步** | 改了上面的作词/作曲/编曲，正文里"词：周杰伦"这类行会**跟着一起改** |

| **导入自动识别** | 拖进来一个 `.txt` / `.lrc` / `.md`，自动扫描作者信息填入上面三行 |
| **导入即全文** | 文件里的**全部内容**都显示在下面的编辑区，只去掉时间轴和 `[ti:]` 标签，想删什么自己删 |
| **智能清洗** | 自动去掉 `[00:12.34]` 时间轴、识别 `[ti:]` `[ar:]` `[al:]` 标签，可开关 |
| **更多信息** | 制作人 / 混音 / 母带 / 吉他 等附加信息自动归类，可增删，默认不占用前三行 |
| **右滑看关于** | 在「歌词模板」卡片上**向右滑动**（或右上角 ⓘ）唤出右侧抽屉 |

| **分级保存** | 信息区、歌词区各有一个「保存」只记录到文档；**最下面**的按钮才真正写回原文件 |
| **实时统计** | 段数 / 行数 / 字数实时显示 |
| **快捷键** | `Ctrl+S` 写回原文件、`Ctrl+O` 导入、`F1` 关于 |
| **最近文件** | 记住最近打开过的 8 个文件 |

### 自动识别支持这些写法

```text
作词：周杰伦          作词 : 周杰伦       作词 周杰伦        词：林夕
【作词】周杰伦         [作词]方文山        缩进 4 格也能认
词曲：周杰伦          词曲编：周杰伦       作词/作曲：周杰伦
Lyricist: Adele      Composer: Adele    Arranger: Paul
[ti:晴天]  [ar:周杰伦]  [al:叶惠美]       制作人：张小博     混音：陈小琴
```

**歌名 / 演唱 的兜底推断**：很多 LRC 文件既没有 `[ti:]`/`[ar:]` 标签，
正文里也不写歌名。这时会按顺序尝试三级兜底：

| 顺序 | 来源 | 例子 |
| --- | --- | --- |
| 1 | `[ti:]` / `[ar:]` 标签 | `[ti:晴天]` → 歌名=晴天 |
| 2 | 开头几行的标题行 | `LOSER - BIGBANG (빅뱅)` → 歌名=LOSER，演唱=BIGBANG，原名=빅뱅 |
| 3 | **文件名** | `晴天 - 周杰伦.lrc` → 歌名=晴天，演唱=周杰伦 |

第 2 级要求有短横线（`晴天 - 周杰伦`，破折号前后各一段）；
第 3 级会自动去掉 `歌词` `完整版` `精校` 这类杂音标记。

宁可空着也不错填：文件名没有短横线、或歌名以句号结尾时都不猜。

> 专辑识别不出来属于正常：LRC 格式本身只在 `[al:]` 标签里存专辑，
> 文件里没写就没法凭空猜出来。

**防误判机制**：只认行首附近的字段；值超过 40 字判定为歌词而非人名；歌词正文里出现的
`我说：xxx` 不会被当成元数据。宁可漏填，也不会乱填。

**导入即全文**：扫描只负责把信息填到上面的输入框，**不会删掉文件里的任何一行**。
下面的编辑区显示文件的全部内容（只去掉 `[ti:]` 这类标签行），
想删哪行自己在编辑区里删，主动权全在你手上。

### 时间轴开关

LRC 里每行都带 `[00:15.000]`，看歌词时很碍眼。正文区右上角有开关
「**隐藏 [00:00.000] 时间轴**」：

- 打开 → 界面只显示歌词；**保存出去的文件也是纯歌词**（所见即所得）
- 关闭 → 显示并导出带时间轴的原文

**只是显示层隐藏，原文不会丢**。在隐藏状态下改歌词，时间轴会按行
自动合并回去，关掉开关它们还在。

- 导入后提示条显示「正文 N 行」，读进来多少一眼可见
- 段落之间的空行会保留，歌词结构不会被压扁
- 点保存时，正文开头与上面三个输入框**重复的信息行会自动去掉**，
  导出的文件里作词作曲不会写两遍
- 如果新文件是空的、而你编辑器里本来有内容，**原内容会被保留**，不会被冲掉

## 二点五、界面与保存机制

```
┌──────────────────────────────────────────────┐
│ [导入歌词] [新建] [关于]          文件名（已保存）│  ← 工具条在最上面
├──────────────────────────────────────────────┤
│ 《xx.lrc》 识别到 6 项…正文 48 行               │  ← 导入结果
├──────────────────────────────────────────────┤
│ ▼ 歌曲信息（作词／作曲／编曲…）      [保存信息] │  ← 导入后自动展开
│   作词[方文山] 作曲[周杰伦] 编曲[钟兴民]        │
├──────────────────────────────────────────────┤
│ 歌词正文              3 段·48 行   [保存歌词]  │
│ 古巴比伦王颁布了汉谟拉比法典                    │
├──────────────────────────────────────────────┤
│ ██████  保存到原文件并覆盖  ██████             │  ← 整行，红色
└──────────────────────────────────────────────┘
```

### 改名自动同步（重要）

导入后正文里常留有"词：周杰伦""曲：周杰伦""编曲：钟兴民"这类行。
在上面把作词改成"张志博"之后，**正文里那几行会跟着一起改**，
不用手动去正文里一个个找着改。

规则：

- **键名保持原样**：原文写"词："就还是"词："，只改冒号后面的名字
- **只动作词/作曲/编曲**：制作人、混音这些不动
- **认不出就跳过**：歌词里的"我说：xxx"不受影响
- **合并键会拆分**："词曲：周杰伦"在作词作曲改成不同的人之后，
  会自动拆成"作词：A""作曲：B"两行
- 信息区底部有开关「**改信息时，同步更新歌词里的名字**」，默认开着，
  不需要就关掉

触发时机：点「保存信息」时，或者直接点最下面的「保存到原文件并覆盖」时
（写盘前会先同步一次，保证落盘的始终是最新名字）。

### 保存分两级

**保存分两级**，这是刻意设计的，避免误操作毁掉原文件：

| 按钮 | 作用 | 会动硬盘吗 |
| --- | --- | --- |
| 信息区旁的「保存信息」 | 把上面几个输入框的修改记进当前文档 | ❌ 不会 |
| 歌词区旁的「保存歌词」 | 把正文的修改记进当前文档 | ❌ 不会 |
| **最下面「保存到原文件并覆盖」** | 把整个文档写回原文件并覆盖 | ✅ **会** |

- 最下面那个按钮点了会**先弹确认框**（覆盖没法撤销），显示文件名让你核对
- 设置页（右上角齿轮）只有一个开关：导出时是否附带歌名 / 制作人等更多信息
- 底部状态栏实时显示 `文件名（信息未保存）` / `文件名（已保存）`，一眼看出有没有忘了存
- 覆盖写入前会清掉正文里重复的信息行，所以**作词作曲不会写两遍**。
  判断依据是**行的键名**（作词/作曲/词/曲/词曲…），不是整行内容相同，
  所以即使把作词从"周杰伦"改成了别人，正文里那行旧的"词：周杰伦"也会被清掉

## 四、电脑上跑起来

### 最省事：双击「启动软件.bat」（推荐）

装好 Python 后，**双击 `启动软件.bat`** 就完事了。它会自动建虚拟环境、
自动装依赖、自动启动，全程不用敲命令。第一次会慢一点（1～3 分钟），
之后双击即开。

> 前提：装 Python 时**必须勾选 `Add Python to PATH`**，否则脚本找不到 Python。
> 没装 Python 的话去 https://www.python.org/downloads/ 下一个，建议 3.11。

**双击后如果是一串看不懂的报错**，按顺序试：

1. 换 **`启动_英文版.bat`**（纯英文，任何情况下都不会乱码）
2. 还不行就双击 **`环境检测.bat`**，把结果截图——它会列出 Python 版本、
   系统代码页、文件是否齐全，一眼就能看出问题在哪

### 手动敲命令

```bash
# 1. 进入项目
cd lyrics-studio

# 2. （推荐）建个虚拟环境，别污染系统 Python
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # macOS / Linux

# 3. 装依赖（必须锁定版本！Flet 各版本 API 差异很大）
pip install -r requirements.txt

# 4. 运行
python main.py
```

开发时想热重载（改代码自动刷新）：

```bash
flet run main.py
```

## 六、打包发布

打完标签推到 GitHub，Actions 会自动构建 Windows 版和 Android APK 并生成 Release：

```bash
git tag v1.0.0
git push origin v1.0.0
```

手动打包命令：

### Windows exe 打包前，先装这两个东西（缺一不可）

| 依赖 | 说明 |
| --- | --- |
| **Visual Studio 2022** | 安装时必须勾选「**使用 C++ 的桌面开发**」工作负载。没它必报 `CMAKE_CXX_COMPILER` 错误 |
| **开发人员模式** | 设置 → 隐私和安全性 → 开发者选项 → 打开「开发人员模式」。没它打包会因不支持符号链接而失败 |

准备好后，**双击 `打包成exe.bat`** 即可，脚本会处理剩下的事。

手动敲命令：

```bash
# Windows 可执行程序
flet build windows --project lyrics_studio --product LyricStudio --org com.zxb
# 产物：build/windows/lyrics_studio.exe（连同 dll、data 一起分发）

# macOS
flet build macos --project lyrics_studio --product LyricStudio --org com.zxb

# Android APK
flet build apk --project lyrics_studio --product LyricStudio --org com.zxb
```

如果提示 `flet: command not found`（Windows 上是「不是内部或外部命令」），
说明 pip 装的脚本目录不在 PATH 里，改用下面这种写法即可：

```bash
python -c "import sys; from flet.cli import main; sys.argv = ['flet'] + sys.argv[1:]; main()" \
    build windows --project lyrics_studio --product LyricStudio --org com.zxb
```

**不想装 Flutter SDK 的话**，改用 PyInstaller 路线（需要先
`pip install "flet[all]==0.25.2" pyinstaller`）：

```bash
python -c "import sys; from flet.cli import main; sys.argv = ['flet'] + sys.argv[1:]; main()" \
    pack main.py --name LyricStudio --icon assets/icon.ico -y
# 产物：dist/LyricStudio/
```

> Windows 上 PyInstaller 只认 `.ico` 格式的图标，传 `.png` 会失败。
> 仓库里已经备好了 `assets/icon.ico`。

> ⚠️ **打包命令里的名字务必用英文！** Flet 0.25 有个已知 bug：项目名或产品名
> 含中文，打包出来的 exe 双击会报 `ImportError: No module named main`。
> `打包成exe.bat` 已经处理好——用英文打包，完成后自动把 exe 改名为中文，
> 效果一样但不踩坑。

### exe 打不开？看这里

打包完成后的 **`build\windows\` 是一个文件夹，不是单个 exe 文件**：

```
build/windows/
├── 歌词修改工作台.exe    ← 主程序
├── flutter_windows.dll   ← 缺了就打不开
├── app.so / python3xx.dll
└── data/                 ← 缺了也打不开
```

分发时**必须把整个 `build\windows` 文件夹压缩后再发给别人**。
最常见的"双击 exe 没反应"，就是只把 exe 单独拷出来了。

## 九、常见问题

**Q：为什么 AI 不能直接给我一个 exe？**
A：**Windows 的 exe 只能在 Windows 电脑上生成**，这是 Flet 官方的构建限制
（构建矩阵里写得很清楚）。我运行在 Linux 环境，物理上生不出来，
所以只能给你源码加打包脚本。

还有一点：**打包出来的也不是一个孤零零的 exe，而是一整个文件夹**。

```
build/windows/
├── 歌词修改工作台.exe    ← 主程序
├── flutter_windows.dll   ← 少一个 dll 就打不开
├── python3xx.dll
└── data/                 ← 这个也不能少
```

所谓"双击 exe 没反应"，十有八九是**只把 exe 单独拷走了**。
分发时得把整个 `build\windows` 文件夹压缩打包。

**Q：打包报「'flet' 不是内部或外部命令」？**
A：pip 把 `flet.exe` 装到了 Python 的 Scripts 目录，而那个目录常常不在 PATH 里，
直接敲 `flet` 就找不到。脚本已改成用
`python -c "from flet.cli import main; main()"` 调用，绕开 PATH，不再依赖命令。

> 顺带修了个同源 bug：`flet build` **没有 `--artifact` 这个参数**，
> 加了会直接报错退出（错误码 2）。云端打包脚本里原来写了这个参数，
> 所以 GitHub Actions 也会失败，已移除。

**Q：打包报「flutter command is not available in PATH」？**
A：`flet build` **要求本机装了 Flutter SDK**，而且它不会自动下载，
必须你自己装好并加进 PATH。

新版脚本已经处理了这个问题：它会**先检测 Flutter**——

| 检测结果 | 走的路线 | 说明 |
| --- | --- | --- |
| 找到 Flutter | `flet build windows` | 原生打包，体积小、启动快 |
| **没找到** | `flet pack`（PyInstaller） | **不需要 Flutter**，功能完全一样，产物稍大 |

所以直接双击 `打包成exe.bat` 就行，**不用手动装 Flutter**。

**Q：本机打包还是失败？**
A：本机打包需要 Visual Studio 2022（必须勾「使用 C++ 的桌面开发」）
+ Windows 开发人员模式，缺任一个都会失败。

**最省事的办法是用云端打包**：代码推到 GitHub，打一个 `v1.0.0` 标签推上去，
GitHub Actions 会自动构建 Windows 版和安卓 APK 并生成 Release，
你直接下载就行，**本机什么都不用装**。

**Q：双击 bat 报「不是内部或外部命令」，中文还是乱码？**
A：这是 Windows 批处理的两类经典坑，脚本已经做了规避：

| 原因 | 说明 | 规避方式 |
| --- | --- | --- |
| **换行符是 LF 不是 CRLF** | 在 Linux/macOS 上生成的 bat，cmd 解析会错乱，把中文当成命令执行 | 所有 bat 一律用 CRLF 换行 |
| **系统代码页不匹配** | 系统是 UTF-8（65001）或英文（437），bat 里的 GBK 中文就会变乱码 | bat 开头执行 `chcp 936`，并额外提供纯英文版兜底 |
| **用了 `^` 续行符** | 续行符遇换行符异常时，会把下一行拼成命令 | 所有命令写成单行，不用 `^` |

如果还不行，直接双击 **`环境检测.bat`** 把结果截图发过来。

**Q：界面起不来，报 `unexpected keyword argument`？**
A：Flet 装成了别的版本。执行 `pip install -r requirements.txt` 锁回 `0.25.2`。

**Q：导入后信息栏都填好了，但歌词正文还是空的？**
A：现在正文区会显示文件的**全部内容**，所以如果还是空的，只可能是——**这个文件本身就是空的**，
或者里面只有 `[00:12.34]` 时间轴、一行字都没有。换一个文件试试。

> 注意：网上下载的 `.lrc` 经常出现**文件名和歌曲内容对不上**的情况
> （比如叫《黑色幽默》但里面是《兰亭序》），信息栏也可能是错的。
> 这种文件建议直接换一个来源重新下载。

**Q：导入后下面一大片灰色，歌词没显示出来？**
A：这是布局问题，已修复。原因是正文区用 `expand` 去抢窗口剩余高度，
一旦窗口较矮、或者展开了「更多信息」，正文区就会被挤成 **0 高度**，
你看到的那片灰色其实是**页面背景**，不是编辑框。

现在改成：正文区保持 16 行的固定高度，页面整体可滚动。
无论窗口多小、上面展开多少，歌词编辑框都实实在在占着地方。

**Q：导入后正文里还留着「作词：xxx」这些行，能自动删掉吗？**
A：故意保留的。导入等于"打开文件"，删不删由你决定。
点保存的时候，正文开头和上面输入框**重复的那几行会自动合并掉**，
所以导出的文件是干净的模板，不会写两遍。

**Q：导入后中文乱码？**
A：程序会依次尝试 UTF-8 / GBK / Big5 等常见编码；极端情况可以先用记事本把文件另存为 UTF-8。

**Q：保存的文件用 Windows 记事本打开是乱码？**
A：不会，程序统一按带 BOM 的 UTF-8 写出，记事本可以正常识别。

**Q：手机上一滑就误触「关于」？**
A：手势只在顶部「歌词模板」那张卡片上生效，正文区域不会误触；也可以只点右上角 ⓘ 打开。

## 开发注意：一个 Flet 布局陷阱

```python
# ✗ 错误：整个 Row 会渲染失败，里面的控件全部消失
ft.Row(wrap=True, controls=[ft.Text("标题"), ft.Container(expand=True), btn])

# ✓ 正确：标题行用普通 Row，撑满宽度靠 expand；换行靠拆成多行
ft.Row(controls=[ft.Text("标题"), ft.Container(expand=True), btn])
```

`wrap=True` 的 Row 在 Flutter 里对应 `Wrap`，而 `Wrap` **不接受 `Expanded`**
（也就是 Flet 的 `expand=True`）。两者同时出现会让整行构建失败 ——
表现是这一行的开关、按钮**凭空消失**，但页面其他地方一切正常，
很容易误判成"功能没做出来"。

项目里有测试守着这条规则（`test_no_row_combines_wrap_and_expand`）。
